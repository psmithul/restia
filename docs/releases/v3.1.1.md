# Restia v3.1.1

Restia v3.1.1 restores access for local profiles whose password is no longer
accepted, without weakening the authentication-store safety boundary.

## Fixed

- Added a polished **Forgot password?** flow to the login screen for source and
  Docker Compose installations.
- Added an owner-only installation recovery key that is generated locally,
  compared in constant time, and rotated after every successful reset.
- Password recovery now revokes existing sessions and unlinks non-local
  identities so stale access cannot survive a reset.
- A verified recovery can safely retire changed legacy authentication files
  into a quarantine directory and restore the database-backed login authority.
- Recovery errors do not reveal whether a profile exists, and attempts are
  rate-limited at the public authentication boundary.

## Upgrade

Docker installs can update with:

```bash
./update.sh
```

After updating, choose **Forgot password?** and retrieve the private recovery
key on the Restia host with either:

```bash
python3 -m src.password_recovery show
docker compose exec odysseus python -m src.password_recovery show
```

The recovery key is stored with owner-only filesystem permissions and is never
sent to an email provider or external service.

## Verification

- Password recovery, auth-store cutover, session revocation, policy, event-loop,
  secret-storage, terminology, and application route tests passed.
- The recovery UI was verified live at desktop width, including validation,
