# Restia v3.1

Restia v3.1 is a slightly-major security release. It replaces the former
"authenticated browser equals unlocked device" assumption with a real
server-verified WebAuthn boundary.

## Shipped

- Passkey enrollment for platform authenticators and security keys, protected
  by current-password and active-TOTP step-up.
- Exact origin and relying-party validation, required user presence and user
  verification, signature-counter validation, encrypted single-session
  challenges, and bounded credential payloads.
- Short-lived device-unlock grants attached to one database-backed session.
  API tokens and ordinary cookies never satisfy the unlock policy.
- Account-owned passkey listing and password/MFA-protected revocation. Password
  rotation and passkey revocation clear existing unlock grants.
- Settings UI for registration, device verification, and revocation, plus an
  honest account security-posture report.
- Independent recurring encrypted backups for local-single deployments:
  database-leased scheduling, verification-before-retention, durable run
  health, configurable retention, hardened external passphrase files, and
  persistent Docker backup/secret mounts. Shared PostgreSQL fails explicitly
  until an operator database plus blob-store backup is configured.
- Owner-scoped read-only Slack and Twilio SMS/call polling with canonical HTTPS
  origins, GET-only preset grants, encrypted durable cursors, bounded imports,
  Communications Hub projection, and no reply/send callable.
- Owner-scoped Finance analysis for classification, cash flow, subscriptions,
  due items, anomaly inputs, net worth, bounded forecasts, and evidence-backed
  affordability scenarios. Finance records and queries cannot transfer,
  invest, purchase, or cancel services.
- Server-owned autonomy levels 1–6, configurable owner/domain caps, immutable
  reviewed proposals, mandatory confirmation for external and high-risk work,
  reversible-action undo evidence, and a deliberately unrepresentable
  WhatsApp send path.
- The release PostgreSQL gate now executes the same canonical identity, Life,
  policy, profile, encryption, and leadership contract as SQLite before any
  image can be built or promoted.
- Alembic revision `20260802_0018`, SQLite/PostgreSQL schema validation, and
  real P-256 WebAuthn registration/assertion tests.
