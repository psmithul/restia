# Restia v3.1.2

Restia v3.1.2 fixes password recovery when a legacy authentication import was
performed on the host and the same data directory is later mounted into the
official Docker image.

## Fixed

- Recovery now recognizes an immutable legacy-auth backup after a host-to-
  container mount changes its absolute path.
- Relocation is restricted to the recorded backup basename inside the current
  installation's backup directory.
- File type, maximum size, symlink rejection, and SHA-256 verification remain
  mandatory before Restia quarantines a changed legacy auth source or unlocks
  the database authority.
- Normal source installs and explicitly configured backup directories keep the
  same fail-closed behavior.

## Upgrade

Docker installs can update with:

```bash
./update.sh
```

After updating, submit **Forgot password?** again with the installation's
recovery key and the desired password.

## Verification

- Auth runtime and password-recovery regression suites passed, including a
  simulated host-to-container relocation and a corrupted-relocated-backup
  rejection check.
- Release version preflight and Python compilation passed.
